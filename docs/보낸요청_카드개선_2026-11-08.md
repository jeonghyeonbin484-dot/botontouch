# 보낸 인수인계 요청 카드 개선

기존 색상·테두리·버튼 체계와 요청·대화·문서 처리 기능을 유지하면서 요청별 독립 카드로 구성했습니다. 받은 요청과 카드 렌더러 및 기본 스타일을 공유합니다.

## 화면

- 업무명과 전달 문서명, 인계자·인수자, 요청일, 현재 상태, 자료 수, 미답변 추가 질문 수, 인수자 검토 상태 표시
- 요청마다 **진행 상황 확인 / 인수인계서 보기 / 대화하기** 제공
- 업무명·문서명·인수자 검색, 상태별 필터, 최근 요청순·최근 처리순·문서명순 정렬, 서버 페이지 조회
- 글자와 버튼 크기를 높이고, 받은 요청과 같은 카드 간격·표시 방식 적용
- 요청 상세의 추가 확인 질문·답변을 바로 펼쳐 인계자가 답변 위치를 찾기 쉽게 정리

## 실제 데이터에 따른 상태

| 구간 | 표시 기준 |
|---|---|
| 요청 전달 | 수신 계정이 연결된 요청은 전달됨. 계정 연결 전은 전달 대기 |
| 인수자 검토 | `requested`는 열람 확인 전, `reviewing`은 열람 확인·검토 중, `needs_info`는 보완 요청. 수락·완료 기록이 있을 때만 해당 결과 표시 |
| 추가 질문·답변 | 실제 인수자 질문 수와 미답변 수 사용. 답변 전달과 인수자의 답변 확인을 구분. 질문이 없으면 추가 질문 없음으로 표시하며 답변 완료를 임의로 만들지 않음 |
| 최종 인수 완료 | `accepted`는 수락 후 최종 완료 대기, `completed`일 때만 최종 완료 |

보완 요청 사유, 미답변 질문, 인수자 확인 대기, 최종 완료 처리 등 현재 필요한 후속 조치를 카드에 안내합니다. 인계자가 진행 상황·미리보기·대화방을 열어도 인수자의 열람 상태를 변경하지 않습니다. 인수 수락은 인수자, 최종 완료·확정본 저장은 인계자라는 기존 권한을 유지합니다.

최근 요청순과 요청일은 `request_snapshots`의 현재 전달 버전 시각을 사용합니다. 재전송한 요청도 새 전달 시각에 맞게 정렬합니다. 이전 자료에 전달 시각이 없으면 기존 생성일로 표시하며, 기존 `created` 필드는 변경하지 않았습니다.

## 문서와 데이터 보존

미리보기는 기존 `/api/requests/{id}/export.html`과 공통 전체 페이지 뷰어를 재사용해 실제 전달 스냅샷을 남양주시 HWPX 서식으로 표시합니다. HWPX 다운로드도 같은 요청 문서를 사용합니다. 완료 건은 기존 확정본 출력 경로를 사용합니다. 이후 변경한 작성 문서를 대신 보여 주지 않습니다.

기존 데이터·계정·요청·자료 삭제나 초기화, 새 테이블 추가, 로그인·조직도·Gemini·공유 DB 설정 변경은 없습니다. 본인이 보낸 요청만 목록에 나타나며 문서·원본 파일은 기존 당사자 권한 검사로 보호합니다.

## 주요 파일

- `web/sent-requests.js`: 보낸 요청 목록·필터·페이지·실제 진행 단계·후속 조치
- `web/received-inbox.js`: 양쪽 화면의 공통 카드 렌더러, 상세 추가 질문 표시
- `request_inbox.py`: 현재 전달 버전의 요청일과 최근 요청순 조회, 기존 필드 호환 유지
- `web/ui.css`, `web/build.py`, `web/index.html`: 공통 카드 스타일과 배포 번들
- `tests/test_sent_requests.py`, `tests/test_sent_requests_browser.py`: 서버 계약과 PC·모바일 기능 검증
- `tests/test_received_inbox_browser.py`: 공통 카드 스타일 적용 후 받은 화면의 페이지 범위로 검증 선택자 보정

## 검증 범위

격리된 공유 DB 대역과 가상 직원으로 PC 1440px·모바일 390px에서 독립 카드, 검색·상태 필터, 실제 처리 단계, 대화 전송, 공식 서식 미리보기·HWPX 다운로드, 추가 질문 답변, 인수자 확인·수락, 인계자의 최종 완료를 검증합니다. 인계자의 조회가 인수자의 열람 상태를 바꾸지 않는지, 타 계정의 목록·문서·원본 접근 차단, 작성 문서 변경 후 전달 스냅샷 보존, 재전송의 실제 요청일 정렬도 확인합니다.

받은 요청, 로그인·공유 저장, 기존 AI 문장 편집·5단계 작성·문서 출력 회귀 검사도 수행합니다. 캡처와 로그는 배포에서 제외하는 `artifacts/sent-requests/`에 보관합니다. 실제 운영 계정의 쓰기 처리나 실제 Gemini·내부 조직도 호출은 실행하지 않습니다. HWPX는 ZIP/XML·텍스트 및 HTML 미리보기 기준이며 한컴오피스 인쇄 배치는 별도입니다. 최종 테스트 수와 GitHub·Vercel 결과는 최종 응답에 보고합니다.

검증 결과: 회귀 61항목 중 전체 실행에서 60항목이 통과했습니다. 받은 화면 테스트 1항목은 공통 스타일의 다른 페이지 요약까지 선택하던 범위를 수정하고 PC·모바일 재검증을 통과했습니다. HTML 번들 빌드·JavaScript 구문·Python 컴파일·Git 공백 검사도 통과했습니다.
