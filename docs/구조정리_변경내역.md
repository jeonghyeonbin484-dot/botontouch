# 기능별 구조 정리

백엔드는 backend/batontouch, 프런트엔드는 frontend/features로 구분했습니다. 기존 API 주소, SQL 스키마, 인증 조건, AI 요청 제한은 변경하지 않습니다.

삭제·이동 기준:
- 이전 최상위 Python 구현은 기능 패키지로 이동하고 호환 모듈을 backend에 둡니다.
- 기존 web 소스는 frontend로 이동합니다. 빌드 결과의 바이트 동일성을 검사합니다.
- 캐시만 삭제합니다. 과거 배포본·미확인 문서는 검증 전 보존합니다.
- 테스트는 보안·파일 추출·AI 구조 검증·전달·채팅·출력 회귀 범위를 보존합니다. 실행기는 가져온 클래스의 중복 실행만 제외합니다.
- judge-test, HWPX 서식, 실제 영상, 사용자 매뉴얼은 보존합니다.
- DB·직원명부·비밀번호·채팅 기록·환경변수는 이동·삭제·초기화하지 않습니다.

복구본은 개발 PC의 artifacts/refactor-backups/20261109-143451에 있습니다. 비공개 설정은 원래 위치에 보존합니다.


검증 결과(2026-11-09): 서버 자동 검사 137건 통과, 실제 Chrome PC·모바일 회귀 12건 통과. DB 스키마 구문 33개와 API 경로 문자열 108개 보존. 초기 빌드의 화면 결과는 이동 전과 바이트 단위로 같았습니다. 이후 기존 보낸 요청 화면의 답변 저장 후 목록 갱신 문제를 수정했습니다. 이 문제는 변경 전 커밋에서도 재현됐으며 서버 데이터 저장은 정상이고 부모 질문 영역 식별자 전달이 누락된 것이 원인이었습니다.

테스트의 AI 응답은 모의 응답이며 실제 Gemini 호출 성공을 새로 검증한 것은 아닙니다. 운영 DB·계정·환경변수는 변경하지 않았습니다.

정리된 Git 저장소는 작업공간 최상위 botontouch 폴더입니다. 기존 상위 작업본과 데이터·비공개 설정·과거 배포 복사본은 복구용으로 보존했으며, 새 저장소와 배포 패키지에는 포함하지 않습니다.


배포 검증: https://botontouch-test.vercel.app 에서 PC(1440)·모바일(390) 로그인 화면 HTTP 200, 비로그인 내부 API HTTP 401, 비공개 설정·Python 소스 경로 HTTP 404, 브라우저 오류 0건을 확인했습니다. 공유 저장소 설정 유지와 AI live·approved-materials·gemini-3.1-flash-lite 설정 유지를 확인했습니다. Vercel 함수 자동 탐지를 위해 api/index.py에 처리기 상속 클래스를 명시했습니다. 이 진입점 변경 후 핵심 HTTP 테스트 10건을 다시 통과했습니다.

이번 작업에서 운영 사이트의 직원 로그인 이후 전체 흐름과 실제 Gemini 호출을 새로 실행한 것은 아닙니다. 전체 흐름은 분리된 가상 저장소와 모의 AI로 실제 Chrome에서 검증했습니다. 운영 계정의 비밀번호를 사용하거나 계정을 새로 만들지 않았습니다.
