# 받은 인수인계 요청 화면 개선

## 건수 차이의 원인과 기준

기존 왼쪽 숫자는 `requested + reviewing` 상태의 합계였으며, 목록은 완료를 포함한 최근 200건이었습니다. 미확인 요청과 전체 목록의 표시 기준이 달랐고, 200건 초과 자료는 목록에서 검색할 수 없었습니다.

- **미확인 / 왼쪽 메뉴 숫자:** `requested` 상태, 즉 열람 확인 기록이 없는 요청. 인수자가 문서 확인 또는 상세 열기를 실행하면 기존 `view` 처리 API로 `reviewing` 상태를 저장합니다. 대화방만 열거나 목록·질문 API를 읽는 것은 열람 확인으로 처리하지 않습니다.
- **진행 중:** 최종 `completed` 이전의 모든 받은 요청. 인수 수락 후 인계자의 최종 완료를 기다리는 건도 포함합니다.
- **전체:** 본인에게 전달된 요청 전체. 완료·검색·필터와 관계없이 집계합니다.
- **검색 결과:** 현재 검색·상태 조건의 전체 결과 수. 20건씩 서버에서 조회하며, 200건 이후도 검색·페이지 이동할 수 있습니다.

과거 요청의 상태나 기록은 일괄 변경하지 않았습니다. 기존 API의 `pending` 필드도 호환성을 위해 유지합니다. 대화 메시지 알림과 업무 알림의 읽음 건수는 요청 문서의 미확인 건수와 별개입니다.

## 화면과 진행 흐름

- 업무명, 전달 문서명, 인계자·인수자, 요청일, 진행 상태, 전달 자료 수, 미답변 추가 질문 수를 카드에 표시합니다. 업무명이 없던 예전 요청은 전달 문서명을 사용합니다.
- 대화하기를 유지하고 **인수인계서 확인**을 추가했습니다. 기존 요청 문서 출력 경로와 공통 전체 페이지 뷰어를 사용해 남양주시 공식 서식으로 표시합니다. 작성자가 나중에 수정한 작업 문서가 아니라 전달된 스냅샷이며, 완료 건은 기존 확정본을 사용합니다.
- 수신 → 문서 검토 → 추가 질문 → 답변 확인 → 인수 완료를 카드와 상세에서 표시합니다. 추가 질문이 없는 수락·완료 건은 해당 단계가 선택 사항임을 표시합니다.
- 추가 질문 답변을 받은 인수자는 **답변 확인 완료**를 명시적으로 저장합니다. 표시된 질문·답변의 버전 토큰과 요청 버전이 서버 최신값과 일치해야 합니다. 새로운 질문·답변·재전송이 있으면 확인 상태가 무효화됩니다.
- **인수 수락은 인수자**, **최종 완료·확정본 저장은 인계자**라는 기존 권한을 유지합니다. 수락 후 완료 대기를 별도로 안내합니다.
- 상세의 긴 본문·연결 자료는 접고, 공식 문서 확인과 질문·처리 버튼을 찾기 쉽게 배치했습니다. 검색·상태·정렬·페이지 및 PC/모바일 카드 간격을 정리했습니다.

## 서버·데이터 영향

- `request_inbox.py`: 본인 계정 범위의 목록·집계·검색·페이지·질문 집계와 답변 확인 처리
- `request_answer_reviews`: 요청·버전·수신 계정별 답변 확인 토큰과 시각을 보관하는 추가 테이블. 기존 테이블·직원 계정·자료 삭제나 초기화 없음
- `handover_requests.py`: 목록·상세 메타데이터 및 인수자 전용 답변 확인 경로 연결. 기존 문서·원본 파일 접근 및 요청 처리 권한 유지
- `handover_journey.py`, `web/journey.js`: 실제 표시한 질문·답변과 확인 토큰 연결
- `web/received-inbox.js`, `web/requests.js`, `web/ui.css`, `web/build.py`, `web/index.html`: 요청 화면·미확인 배지·공통 기존 위젯 연동과 배포 번들
- `tests/test_received_inbox.py`, `tests/test_received_inbox_browser.py`: 서버 권한·건수·스냅샷·페이지와 PC/모바일 처리 흐름 검사

공유 DB·로그인·조직도·Gemini 설정·HWPX 양식·요청 문서 내용은 변경하지 않았습니다. 받은 목록은 조직도 조회 성공 여부와 독립적으로 조회합니다. 요청 상세의 표시 중에 요청 버전이 바뀌면 자동으로 새 버전에 대한 승인을 보내지 않고 다시 불러오도록 안내합니다.

## 검증과 한계

격리된 공유 DB 대역과 가상 직원으로 검증했습니다. 운영 계정으로 문서·질문·발송·인수 처리하지 않았습니다.

- 미확인/진행 중/전체/필터 결과의 구분, 문서 확인과 대화 읽음의 분리
- 요청 카드 필드, 이름·업무명 검색, 완료 필터, 205건 페이지·검색
- 다른 직원의 상세·HTML·HWPX·Word·MD·원본 파일·질문·답변 확인 접근 차단
- 수신자 재지정 시 이전 수신자 접근 차단, 새 수신자의 미확인 건수
- 작성 문서 변경 후에도 전달 스냅샷의 미리보기·다운로드 유지
- 답변 확인 토큰·요청 버전 충돌 거부, 재접속 후 확인 상태 보존
- PC 1440px·모바일 390px에서 대화 전송, 문서 열람, 실제 HWPX 다운로드, 추가 질문, 답변 확인, 수락·최종 완료 및 가로 넘침 검사
- 기존 로그인·공유 저장·AI 문장 수정·5단계 작성·전체 문서 출력 회귀 검사

실제 Gemini·내부 조직도 서버 호출과 운영 인수자 계정으로의 쓰기 검증은 수행하지 않았습니다. HWPX는 ZIP/XML·텍스트와 HTML 미리보기를 확인하며 한컴오피스의 실제 인쇄 배치는 별도입니다. 테스트 로그와 화면 캡처는 배포에서 제외하는 `artifacts/received-inbox/`에 보관합니다. 최종 테스트 수·커밋·배포 URL과 상태는 최종 응답에 보고합니다.

최종 결과: 선택한 서버·브라우저 회귀 테스트 **57개 통과**, 실패·오류 0개. HTML 번들 빌드, JavaScript 구문, Python 컴파일, Git 공백 검사도 통과했습니다.
