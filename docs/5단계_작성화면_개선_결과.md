## 사용 방법

1. 홈에서 **인수인계 시작하기**를 누릅니다.
2. 업무명을 저장하고 파일을 등록합니다. 등록이 끝나면 **다음: AI 초안 작성**이 활성화됩니다.
3. Gemini로 초안을 만들고 직접 수정합니다. **다음: AI 예상 질문·답변**을 누르면 변경 내용을 저장한 뒤 이동합니다.
4. **AI 예상 질문 만들기**를 누릅니다. 자료 근거가 있는 추천 답변과 추가 확인이 필요한 답변을 구분합니다. 질문과 답변을 수정하고 **답변 확인·저장**을 누릅니다. 문서 포함 미리보기로 전달 내용을 확인합니다. 불필요한 질문은 제외하거나 전달 체크를 해제할 수 있습니다.
5. Q&A 확인란을 체크하고 후임자 부서와 직원을 선택합니다.
6. 최종 문서를 검토하고 인수인계를 요청합니다. 후임자는 받은 요청에서 문서와 선택한 Q&A를 함께 확인합니다.

작업 바로 아래에 목적지가 표시된 다음 버튼이 있습니다. 작업 영역이 길어 버튼이 화면 밖에 있으면 하단 고정 버튼을 제공합니다. 원래 버튼이 완전히 보이면 고정 버튼을 숨깁니다. 이전 단계로 돌아갈 수 있으며 단계 이동 전 문서와 입력한 Q&A를 저장합니다. 저장에 실패하면 다음 단계로 이동하지 않습니다.

## 구현 내용

- 단계별 현재 위치, 완료 체크, 간결한 작업 안내, 필수 입력 안내와 다음 버튼 활성화 조건
- 기존 자료·AI 초안·조직도·요청 모듈 재사용
- AI 예상 질문 및 자료 기반 추천 답변 생성, 출처 검증, 근거가 없으면 추가 확인 필요 표시
- 질문·답변 직접 편집, 수동 질문 추가, 관련 자료 첨부, 전달 여부 선택, 문서 포함 미리보기
- 질문 제외는 논리 제외로 처리하며 원문과 변경 이력을 보존
- 예전 질문은 이전 확인 질문·답변 영역에 보존
- 후임자 요청 상세 화면 및 HWPX에 선택한 Q&A 연결
- 실제 Gemini 응답과 모의 응답 명확히 구분
- 일반 직원에게 공개하지 않는 새올 ID 원문을 UI에서 요구하지 않고 서버의 검증된 수신 가능 여부를 사용

## 실제 브라우저 검증

실제 Chrome 브라우저를 Playwright로 자동 조작했습니다. 사람의 사용성 평가나 실제 직원 계정 테스트로 대신 표시하지 않습니다. 기존 직원의 비밀번호는 사용하거나 변경하지 않았습니다.

| 항목 | 결과 |
|---|---|
| 가상 일반 직원 로그인 및 5단계 화면 | PASS |
| 가상 PDF·XLSX·HWPX 등록·추출 | PASS |
| 실제 Gemini 초안 생성 | PASS · 서버 API HTTP 201 · 10.85초 |
| 실제 Gemini 예상 Q&A 생성 | PASS · 서버 API HTTP 201 · 7.63초 · 8건 |
| 실제 원문 출처 연결 | PASS · 20개 |
| 초안·답변 수정과 단계 이동 전 자동저장 | PASS |
| 후임자 지정·요청 발송·Q&A 수신·수락 | PASS |
| 선택 Q&A가 포함된 HWPX 생성·XML 내용 검사 | PASS |
| 제3자 요청 접근 차단 | PASS · HTTP 403 |
| 390px 화면 가로 넘침 검사 | PASS |
| 최종 배포 후 수동 Q&A·요청 전달 재검증 | PASS · 추가 AI 호출 없음 |
| 최종 배포 후 일반/고정 진행 버튼 중복 표시 방지 | PASS |

Gemini 모델은 `gemini-3.1-flash-lite`입니다. 이번 실제 Gemini 검증은 총 4회(초안 2회, 예상 Q&A 2회)였습니다. 첫 실행에서 AI 두 기능은 성공했으나 일반 직원의 후임자 선택 후 진행 조건 오류가 발견되어 수정 후 다시 검증했습니다. 이 최초 실행은 전체 흐름 PASS로 표시하지 않습니다. 모의 검증에서는 실제 API를 호출하지 않았습니다. API 키·비밀번호·쿠키는 결과물에 포함하지 않았습니다.

## 데이터 보존

변경 전 Supabase SQLite 스냅샷을 로컬 비공개 폴더에 백업하고, 복제본에서 마이그레이션을 검증했습니다. 기존 `followups`에 기본값이 있는 새 컬럼을 추가하는 방식입니다. 기존 질문·답변·처리 상태와 이력은 삭제하지 않습니다. 구버전 백업도 호환하며 새 Q&A의 추천 답변·근거·전달 여부·이력 복원도 테스트했습니다.

기존 직원 계정 2,832개의 아이디·비밀번호 해시·권한·활성 상태가 작업 전과 일치함을 확인했습니다. 기존 테이블의 레코드 ID가 보존되어 있습니다. 검증을 위해 생성한 임시 가상 계정·자료·요청만 소유 확인 후 정리했고 감사 로그는 유지했습니다. Neon DB는 변경하지 않았습니다.

## 검증 범위와 한계

- 실제 내부 조직도 서버를 새로 동기화하지 않았습니다. 기존 연동과 서버 수신 권한 검사는 그대로 사용합니다.
- HWPX는 다운로드·ZIP/XML 구조와 선택 Q&A 포함을 검사했습니다. 이번 UX 작업에서 한컴오피스의 전체 페이지 배치를 다시 검증하지는 않았습니다.
- AI 추천 답변은 최종 사실 확인을 대신하지 않습니다. 원문 근거와 인계자 확인 여부를 따로 표시합니다.
