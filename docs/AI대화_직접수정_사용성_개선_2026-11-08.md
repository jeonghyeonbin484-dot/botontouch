# AI 대화·문서 직접 수정 사용성 개선

기존 색상·카드·대화·공식 문서 양식을 유지하면서 미리보기와 수정 요청을 연결했습니다. 앞서 완료한 5단계 작성 화면 개선도 같은 배포 대상에 포함합니다.

## 사용자 흐름

1. 문서의 수정할 원문 문단을 클릭하면 가까이에 **AI 수정 요청** 버튼이 나타납니다.
2. 일반 화면에서는 선택한 원문과 짧은 수정 지시 버튼이 대화 입력창에 표시됩니다. 선택하지 않은 경우 이 영역은 숨깁니다.
3. 미리보기 도구 모음 오른쪽의 **전체 화면** 버튼을 누르면 넓은 화면으로 전환합니다. 전체 화면에서도 원문 선택 → 수정 지시 → AI 제안 → 전후 비교 → 승인/취소를 처리합니다.
4. **수정 반영**을 눌렀을 때만 기존 저장 API가 선택한 위치를 수정합니다. 다른 문단은 유지하며, 미리보기와 HWPX가 같은 저장 문서를 사용합니다. 기존 되돌리기와 수정 이력을 유지합니다.
5. 대화·문서를 전환하거나 문서 버전이 변경되면 선택한 위치와 연결된 수정 지시를 해제합니다. 서버의 문서 지문·위치·첨부자료 수정 번호 검사는 그대로 유지합니다.

PC에서는 두 영역 사이의 경계선을 드래그하거나 방향키로 조절합니다. 더블 클릭하면 기본 비율로 돌아갑니다. 비율은 사용자별 브라우저 설정으로 보존하며 모바일에서는 기존 대화/문서 탭을 사용합니다.

시작 화면은 첨부자료가 있으면 연결된 자료 개수와 초안 작성 요청을 안내하고, 자료가 없으면 자료 첨부 또는 담당 업무 입력을 안내합니다. 빈 대화창의 고정 높이를 줄였습니다.

## 영향 범위

- `web/studio-editing-ux.js`: 영역 너비 조절, 전체 화면 수정 UI, 시작 안내, 선택 상태 보강
- `web/studio-document-preview.js`: 전체 화면 유지·버튼 배치·원문 근처 수정 버튼
- `web/studio-paragraphs.js`: 전체 화면 선택 전달과 문서/업무/버전 결합 검사
- `web/ui.css`, `web/build.py`, `web/index.html`: 스타일과 배포 번들
- `tests/test_studio_editing_ux_browser.py`, `tests/test_studio_paragraphs_browser.py`: PC·모바일 회귀 검사

이번 AI 화면 개선은 기존 Gemini 호출·수정 제안·승인·되돌리기 서버 로직을 재사용합니다. 직원 계정, 비밀번호, 조직도 연동, 공유 DB 연결 설정, 공식 HWPX 양식을 변경하거나 초기화하지 않았습니다.

## 검증 범위

격리된 공유 저장소와 가상 계정으로 PC 1440px·모바일 390px에서 검증합니다. 영역 조절·비율 복원, 자료 유무별 시작 안내, 일반/전체 화면 선택, 승인 전 문서 불변, 취소·반영·되돌리기, 다른 문단 보존, 문서 전환 시 선택/지시 해제, 실제 HWPX 다운로드의 승인 내용 포함을 검사합니다.

실제 운영 계정으로 문서를 생성·수정·발송하지 않습니다. 실제 Gemini 및 내부 조직도 서버 호출은 이번 검증 범위에 포함하지 않습니다. 운영 사이트의 공개 로그인과 저장소 상태는 읽기 전용으로 확인합니다. HWPX는 ZIP/XML·텍스트 내용을 확인하며 한컴오피스 인쇄 배치를 새로 검수하지 않습니다.

브라우저 캡처와 실행 로그는 배포에서 제외하는 `artifacts/studio-editing-ux/`에 보관합니다. 최종 테스트 수·커밋·배포 URL은 최종 응답에 보고합니다.

검증 결과: 서버·브라우저 회귀 87항목을 확인했습니다. 전체 실행에서 86항목이 통과했고, 너비 복원 테스트 1항목은 화면 초기화 완료 전 값을 읽어 실패했습니다. 복원 완료 대기 조건을 보정한 뒤 해당 PC·모바일 테스트가 통과했습니다. HTML 번들 빌드·JavaScript 구문·Git 공백 검사도 통과했습니다.
