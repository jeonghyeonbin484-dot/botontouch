# 대화 알림 사용 방법 및 운영 범위

## 사용 방법

1. 바통터치에 로그인하고 상단의 본인 이름을 누릅니다.
2. 대화 알림 설정을 선택합니다.
3. 알림음 사용을 켜거나 끌 수 있습니다. 미리 듣기로 확인하세요. 브라우저 정책에 따라 로그인 후 사이트에서 한 번 클릭해야 소리가 날 수 있습니다.
4. PC 알림이 필요하면 브라우저 알림 켜기를 누르고 허용합니다. 사이트 접속만으로 권한을 요청하지 않습니다.
5. 다른 화면에서 새 메시지를 받으면 우측 상단에 발신자·업무명·내용 일부가 표시됩니다. 알림을 누르면 해당 대화방이 열립니다.
6. 대화방을 실제로 열고 최신 메시지까지 표시했을 때 읽음 처리됩니다. 읽음과 미읽음은 서버에 저장되어 새로고침·재로그인 후에도 유지됩니다.

알림음과 PC 알림 설정은 브라우저의 사용자별 설정입니다. 다른 PC나 다른 브라우저에서는 다시 설정해야 합니다. 시크릿 창이나 브라우저 저장소 제한에 따라 설정이 유지되지 않을 수 있습니다.

## 구현 범위

- 기존 메시지·읽음 테이블 및 세션 인증을 재사용합니다. DB 초기화나 기존 이력 삭제는 없습니다.
- 전체 화면용 SSE: /api/chat/notifications/events. 누락 동기화 및 상태 조회: /api/chat/notifications.
- 서버는 요청마다 로그인 세션을 확인하고 인계자·인수자로 참여한 현재 대화방의 메시지만 반환합니다. 자기 메시지는 알림에서 제외합니다. 첨부파일은 원문 파일이 아닌 첨부 도착 안내만 포함합니다.
- 로컬 서버는 열린 연결에서 짧은 간격으로 확인합니다. 현재 Vercel의 DB 트랜잭션·응답 버퍼 구조에서는 짧은 SSE 응답 후 약 5초 간격으로 재연결합니다. 네트워크·DB 상황과 브라우저의 백그라운드 제한에 따라 더 늦을 수 있으며, 항상 즉시 도착함을 보장하지 않습니다.
- 연결 단절 뒤 커서 이후의 새 미읽음 메시지를 50개씩 재조회합니다. 이미 읽은 메시지는 다시 알리지 않습니다.
- 지원하는 HTTPS Edge·Chrome에서는 Web Locks와 BroadcastChannel로 같은 직원의 여러 탭이 알림 연결 하나를 공유합니다. 탭별 중복 표시와 브라우저 알림 중복을 방지합니다.
- 서버 오류 시 재연결 간격을 최대 60초까지 늘립니다. 기존 30초 확인 타이머를 중복 실행하지 않습니다.
- 알림 메시지와 사람 간 대화는 외부 AI에 자동 전송하지 않습니다. 알림 내용은 서버 로그에 기록하지 않습니다. 브라우저 저장소에는 사용자별 설정·커서·중복 방지 번호만 저장하며 메시지 본문을 보관하지 않습니다.

## Supabase Realtime 검토

현재 PostgreSQL에는 SQLite 스냅샷이 bytea로 저장됩니다. 채팅 메시지는 독립된 PostgreSQL 행이 아니므로 메시지별 Realtime 변경 구독을 그대로 적용할 수 없습니다. 기존 로그인도 Supabase Auth JWT가 아닌 자체 서버 세션입니다.

안전한 전환에는 채팅 이벤트용 네이티브 테이블 또는 outbox, 사용자별 짧은 수명의 인증 토큰 연결, 참여자에 대한 RLS와 private channel 권한이 필요합니다. 데이터가 든 스냅샷을 공개 구독하거나 서비스 키를 브라우저에 제공하는 방식은 사용하지 않았습니다. 이 작업에서 Supabase Realtime을 구현했다고 주장하지 않습니다.

접속자 수가 크게 증가하면 현재 스냅샷 저장 방식과 Vercel 호출량을 실측하고, 이벤트 테이블 및 인증 연계를 별도 마이그레이션으로 진행해야 합니다. 현재 검증은 소수의 가상 계정 범위이며 전 직원 동시 접속 부하 검증은 하지 않았습니다.

공식 문서: [Supabase Realtime 권한](https://supabase.com/docs/guides/realtime/authorization), [Vercel 스트리밍](https://vercel.com/docs/functions/streaming-functions).

## 사이트를 완전히 닫은 상태의 알림

이번 기능은 사이트 탭이 열려 있는 동안 동작합니다. 사이트 종료 상태 알림은 구현하지 않았습니다. 향후 Service Worker와 Web Push, 구독 저장, VAPID 키, 권한 철회·로그아웃 시 구독 해제, 대화방 접근 권한 재검사가 필요합니다. 푸시 경로에는 본문 대신 알림 식별자만 전달하고 로그인 후 본문을 조회하는 방식을 권장합니다. 브라우저 푸시 서비스로 전달되는 정보와 기관 정책을 별도 검토해야 합니다.

참고: [MDN Push API](https://developer.mozilla.org/en-US/docs/Web/API/Push_API).
